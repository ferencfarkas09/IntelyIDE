# Internationalisation (i18n) and accents

How IntelyIDE translates its interface, how to add or migrate strings, and how accent colours work. Runtime and tooling live in `ui/src/i18n/` and `scripts/i18n-*.mjs`; accents in `ui/src/theme/accents.ts`. The rule for everyone: **all new UI strings go through `t()`**.

## 1. Runtime

```ts
import { t, fmt, locale, setLocale, nameOf } from "../../i18n";
t("tabs.close", { title: tab.title });       // reactive: call it inside JSX, createMemo or createEffect
t("keyboard.conflicts", { count: 3 });       // ICU plural
fmt.number(1234.5); fmt.date(new Date()); fmt.relative(-1, "day"); fmt.list(["a", "b"]);
await setLocale("de");                       // flips once the catalog is loaded; English switches synchronously
```

- **Catalogs**: `ui/src/i18n/locales/<lang>/<namespace>.json`, flat `area.thing` keys. Namespaces (one file each) are listed in `NAMESPACES` in `ui/src/i18n/index.ts`, for example `platform` (palette, settings dialog, tab strip), `shell` (rail, splash, title bar), `settings` and `about`. A namespace is a file: register a new one in `NAMESPACES` (`i18n/index.ts`) and add the static `import` of its English file there (that import gives `t()` its typed keys).
- **Loading**: English is bundled (source of truth and fallback). Every other language is a lazy Vite chunk (`import.meta.glob`), fetched only when it is the active language: the 50 other catalogs cost nothing at runtime. Lookup is `lang-region -> lang -> en` (`pt-BR -> pt -> en`), a missing key shows the English text and, in development, one `console.warn` per key.
- **Messages** (ICU-lite, `i18n/message.ts`): `{name}`; `{n, plural, =0 {none} one {# file} other {# files}}` (categories from `Intl.PluralRules`, `offset:N`, `#` = the formatted number); `{x, select, a {..} other {..}}`; `{n, selectordinal, ...}`; `{n, number[, percent|compact|integer]}`; `{d, date[, short|medium|long|full]}`; `{d, time}`; `{n, relative, day}` (a Date value picks the unit); `{items, list[, and|or|unit]}`. Apostrophes are literal (`l'état`), `''` is one apostrophe, `'{'` quotes a brace.
- **Language selection**: stored in `intely.locale` (localStorage mirror) and in settings.json `general.language`. First run (nothing stored): `navigator.languages` is matched onto a shipped language (`de-AT -> de`, `pt -> pt-BR`, `zh-TW -> zh-Hant`, `no -> nb`, `iw -> he`, ...) and not persisted until the user picks one. `localeReady` (a promise) is awaited before the first render so the first paint is not English.
- **Language names** are shown in their own language (`Intl.DisplayNames`, with a fixed table for `zh-Hans`, `zh-Hant`, `pt-PT`, `pt-BR`, `sr`, `fil`). The picker in Settings > General has a search field (matches own name, English name, current-language name and code), keyboard navigation (arrows + Enter) and an `MT` tag on machine-translated languages.
- **Machine-translation notice**: every language except `en` and `hu` is machine translated (`reviewed` flag in `languages.ts`); Settings > General shows "Machine translated, corrections welcome" for them.
- **RTL**: `ar`, `he`, `fa`, `ur` set `dir="rtl"` (and `lang`) on `<html>`. Use logical properties in new CSS (`margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `border-inline-end`, `text-align: start`, `border-start-end-radius`). Physical `left/right` stay only where the geometry is physical (the segmented control's measured thumb, the window title bar). `theme/rtl.css` keeps code, pre, kbd, the CodeMirror editor and merge view, xterm, diffs, paths, hashes, the file tree and monospace values left-to-right (`direction: ltr; unicode-bidi: isolate`) and sets `--ui-dir` (1 or -1) for transforms.
- **Fonts**: the system stack covers non-Latin scripts; `theme/rtl.css` names the right system families per `:lang()` (Hiragino/PingFang/Apple SD Gothic Neo, SF Arabic/Geeza Pro, Thonburi, Kohinoor/Sangam families) and raises line height for CJK, Thai and Indic scripts.
- **Pseudo-locale `en-XA`** (development builds only, shown in the picker): accented letters and about 40 percent padding in `[ ... ~~~ ]`. Use it to find overflow: set `localStorage["intely.locale"] = "en-XA"` and reload.

## 2. Adding or migrating strings

1. Find what is left: `pnpm i18n:extract` (per-module summary) and `pnpm i18n:extract -- --dir=ui/src/modules/<module>` (every finding as `file:line kind "text"`). It is a heuristic scanner: JSX text, `title / aria-label / placeholder / alt / label / description / tooltip` attributes, the same names as object props (`prop?`, lowest confidence) and `toast.*("...")`. Silence a false positive with an `i18n-ignore` comment on the line.
2. Add the English text to the module's namespace JSON (`locales/en/<ns>.json`), key `area.thing`, ICU for counts (never `"" + n + " file" + (n === 1 ? "" : "s")`) and placeholders for dynamic parts (never concatenate sentence fragments: word order differs between languages).
3. Replace the literal with `t("area.thing", { ... })`. Constant tables (labels in a module-level array) become getters or store the key and call `t()` at render time, so they follow the language: `const KEY = { off: "safety.jail.off.label" } as const satisfies Record<..., MessageKey>`.
4. Write the Hungarian text in `locales/hu/<ns>.json` if you can (`hu` is the reviewed language); leave the rest to the translation script.
5. `pnpm i18n:check` (catalog consistency) and the module's vitest. `catalogs.test.ts` also fails when a literal `t("key")` in the source has no English key.
6. Not translated on purpose: product names (IntelyIDE, IntelyHome, Claude, Git, GitHub, Tauri), file names and paths, branch and ref names, commit messages, env var names (`INTELY_READONLY`), code, CLI flags, keyboard chord glyphs.

Dynamic content that is data (command titles registered by modules, repo names, branch names, error text from Rust or git) is not in the catalogs. Module-registered command titles and groups are migrated when the module registering them is migrated.

### Migration status
Not every screen is migrated yet. Run `pnpm i18n:extract` for the current count of remaining literals per module; `ipc` findings are mostly mock fixture text that does not need translating.

## 3. Translations

`scripts/i18n-translate.mjs` (`pnpm i18n:translate -- --lang=de,fr` or `--all --only-missing`) translates the English catalogs with the `claude` CLI (Haiku, no tools, empty working directory, at most 3 calls in flight, a hard budget of 400 calls recorded in `.scratch/i18n-translate/state.json`). Per language: batches of 60 strings, a system prompt with the glossary rules (git terms keep their usual local form: commit, push, branch, diff, stash, rebase, token, repo, terminal; product names, paths, env vars and flags untouched), the exact plural categories of the language and its script/register notes; every answer is validated (placeholder parity, ICU syntax, plural categories) and failing keys are re-asked up to two times. Then `pnpm i18n:check` is the gate.

`pnpm i18n:check` (`scripts/i18n-check.mjs`, also run by `catalogs.test.ts`): same files and exactly the keys of English, no empty values, identical placeholders, valid ICU, plural categories valid and complete for the language (`Intl.PluralRules`), text in the expected script (at least 30 percent of the letters Cyrillic for ru/uk/bg/sr/mk, Arabic for ar/fa/ur, ...; product and git terms are ignored), plus warnings for length ratios (layout risk) and strings identical to English. `--lang=de,fr` limits it, `--quiet` hides warnings.

Re-translating after English changed: edit `locales/en/*.json`, then `node scripts/i18n-translate.mjs --lang=<codes>` (it rewrites those catalogs completely; budget is counted in the state file). Hungarian is hand written and never overwritten by `--all`.

### Review status
- `en`: source. `hu`: written and reviewed by hand (reviewed).
- All other languages: **machine translated, not reviewed** (Haiku). Corrections are welcome: edit the JSON, keep the placeholders, run `pnpm i18n:check`, and set `reviewed: true` in `languages.ts` only when a native speaker checked the whole catalog.

### Delivered languages
The catalog folders under `ui/src/i18n/locales/` are the list: `en` (source), `hu` (hand written), and the machine-translated languages (Latin, Cyrillic, Greek, Arabic-script, Hebrew, Indic, Thai, CJK and others, including the right-to-left `ar`, `he`, `fa`, `ur`). The development-only pseudo-locale `en-XA` has no folder. Namespaces listed in `PENDING_NAMESPACES` (`scripts/i18n-check.mjs`) are still to be machine translated: `pnpm i18n:check` reports them as warnings in every language except `en` and `hu`.

Known weak spots of machine translation: glossary-heavy strings can end up mixed-script (a Bulgarian or Serbian sentence with a Latin git term in it), and short noun phrases are sometimes left in English. A native review is the next step for every language that is not `hu`.

### Back-translation spot check
`node scripts/i18n-translate.mjs --backcheck=hu,de,fr` (any comma-separated list of codes) translates a sample of strings back to English with the same model and compares them with the source by word overlap. It is a rough screen: a synonym lowers the score, a wrong meaning lowers it more, so read the weakest strings by hand. It is not a review: Hungarian is the only catalog a human wrote.

## 4. Accents

Settings > Appearance offers 11 families (Violet is the brand default from the B2 logo and is hand-tuned in `tokens.css`; Indigo, Blue, Cyan, Teal, Green, Amber, Orange, Rose, Pink, Graphite are generated) and a **Custom colour** (colour picker + hex field; hue and chroma are kept, the lightness is solved so that text stays AA in both themes, and a note shows the colour actually used).

- Generation (`theme/accents.ts`): OKLCH hue/chroma per family, lightness solved per theme so that the on-accent ink reaches at least 4.5:1 on the base, hover and active fills, the accent text/focus colour reaches at least 4.5:1 on all five surfaces and on its own subtle tint, and the fill is at least 3:1 against the raised surface. Light-ink families use white on a mid-dark fill; Amber uses dark ink on a light fill.
- Tokens per accent and theme: `--accent`, `--accent-hover`, `--accent-active`, `--accent-text`, `--accent-subtle`, `--accent-subtle-hover`, `--accent-border`, `--focus-color`, `--text-on-accent`, `--surface-selected`, `--selection-bg`. Families whose colour sits next to a status colour (Teal, Green, Amber, Orange, Rose, Pink) also repoint `--status-modified` to `--info`, so "modified" stays apart from added / untracked / deleted / renamed.
- Application: one `<style id="intely-accent">` with `:root[data-accent][data-theme="dark|light"]` rules; written synchronously from the `intely.appearance` localStorage mirror inside `initTheme()` (before the first render, no flash), then kept in sync with settings.json (`appearance.accent`, `appearance.customAccent`). The logo gradient and the brand mark do not read the accent tokens.
- Tests: `theme/accents.test.ts` holds the contrast table for every family in both themes, the custom-colour sweep (yellow, black, white, grey, neon...) and the application logic. The picker is a radio group (arrow keys, Home, End), with a visible selected state, and a sample card showing button, link, chip, focus ring and selected row.

## 5. Namespaces that are still pending translation

Namespaces in `PENDING_NAMESPACES` (`scripts/i18n-check.mjs`) are written in English and hand-written Hungarian; the other languages hold empty `{}` files until `pnpm i18n:translate` has run for them and the names leave the list. Errors, switch warnings and busy states of the workspace screens are codes from Rust, translated in the UI (`ui/src/shell/workspace/errors.ts`; an unknown code shows `ws.error.generic`), so Rust never sends English text for those screens. `shell/workspace/keys.test.ts` asserts that every literal key the workspace screens use exists in `en` and `hu` with the same keys and placeholders.

The `happy` namespace (Team chat, My tasks, Time Tracer, Inbox and Meet: key prefixes `hc.`, `ht.`, `htm.`, `hn.`, `hm.`, plus the shared `hx.`) was added with the Wave-5c sweep, together with the new `pv.*` / `pvi.*` keys of the Preview module (in the `preview` namespace) and the `providers` namespace; all three are in `PENDING_NAMESPACES`, so the other 51 languages hold `{}` (or lack the new keys) until the translation run. Command groups registered as plain English names (`View`, `Git`, `File`, `Edit`, `Agents`, `Tabs`, `Workspace`) are mapped to `group.*` keys by `groupLabel` in `platform/commands.ts`, which the palette uses for headings, the group chip and the sort order.
